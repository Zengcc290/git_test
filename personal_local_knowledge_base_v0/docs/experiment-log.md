# 实验记录：个人本地知识库搜索工具 V0

## 2026-08-10：V0 初版

### 目标

先验证“本地文档 → 可检索文本 → 关键词命中”的最小闭环，不引入聊天机器人、向量数据库或远程服务。

### 环境

- Windows PowerShell
- Python 3.12.4
- 项目解释器：`.venv/Scripts/python.exe`
- 数据库：Python 标准库 `sqlite3` + SQLite FTS5
- PDF 抽取：`pypdf`

### 实验步骤与结果

| 编号 | 实验 | 结果 |
| --- | --- | --- |
| 1 | 对 TXT、Markdown 做 UTF-8 读取、换行统一、空白压缩 | 通过，保留 Markdown 标题文字 |
| 2 | 按空行聚合段落，超长段落按边界切分并保留重叠 | 通过，可配置 `chunk_size` 和 `overlap` |
| 3 | 使用 SQLite 外部内容 FTS5 表和触发器同步分段 | 通过，文档替换后旧内容不再命中 |
| 4 | 用 SHA-256 判断文件是否变化 | 通过，重复索引会跳过未变化文件 |
| 5 | 命令行搜索并输出路径、分段编号和命中高亮 | 通过，支持 ANSI 颜色和 `--no-color` |
| 6 | 对单个坏文件记录异常并继续处理其他文件 | 已实现，失败计数会显示在索引摘要 |

### 当前结论

V0 已经满足本地文档搜索引擎的最小功能闭环，适合个人少量文档的实验和后续迭代。单元测试覆盖清洗、分段、高亮、数据库替换和增量索引。

### 已知限制

1. PDF 目前只抽取文本层，扫描版 PDF 需要 OCR，暂未支持。
2. FTS5 的 `unicode61` 适合英文及空格分词文本；中文连续词在无 FTS5 命中时使用参数化 `LIKE` 兜底，排序能力有限。
3. 搜索使用关键词 AND 匹配，不支持自然语言理解、同义词和语义检索。
4. 暂未实现已删除源文件的自动清理，需要后续增加 `prune` 命令。

### 下一步实验

- 增加中文分词或 n-gram tokenizer，比较召回率。
- 增加 PDF、超长文档和重复索引的基准数据。
- 增加删除/同步策略，再评估是否需要向量检索。
