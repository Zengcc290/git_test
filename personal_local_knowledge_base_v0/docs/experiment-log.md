# 实验记录：个人本地知识库搜索工具 V0

## 2026-08-10：V0 初版

### 目标

先验证“本地文档 → 可检索文本 → 关键词命中”的最小闭环，不引入聊天机器人、向量数据库或远程服务。

### 环境

- Windows PowerShell
- Python 3.12.4
- 项目解释器：`.venv/Scripts/python.exe`
- 数据库：Python 标准库 `sqlite3` + SQLite FTS5
- PDF 抽取：`pypdf`
- PPTX 抽取：`python-pptx`

### 实验步骤与结果

| 编号 | 实验 | 结果 |
| --- | --- | --- |
| 1 | 对 TXT、Markdown 做 UTF-8 读取、换行统一、空白压缩 | 通过，保留 Markdown 标题文字 |
| 2 | 按空行聚合段落，超长段落按边界切分并保留重叠 | 通过，可配置 `chunk_size` 和 `overlap` |
| 3 | 使用 SQLite 外部内容 FTS5 表和触发器同步分段 | 通过，文档替换后旧内容不再命中 |
| 4 | 用 SHA-256 判断文件是否变化 | 通过，重复索引会跳过未变化文件 |
| 5 | 命令行搜索并输出路径、分段编号和命中高亮 | 通过，支持 ANSI 颜色和 `--no-color` |
| 6 | 对单个坏文件记录异常并继续处理其他文件 | 已实现，失败计数会显示在索引摘要 |
| 7 | 抽取 PPTX 幻灯片文本框、表格和组合图形文字 | 已实现，继续进入清洗、分段和 FTS5 索引 |
| 8 | 将大文件抽取、清洗、分段和数据库写入改为流式 | 已实现，避免全文和全部分段同时驻留内存 |
| 9 | 使用 jieba 生成中文词索引，并以原始 FTS5/LIKE 分级兜底 | 已实现，FTS5 BM25 负责相关性排序 |

### 当前结论

V0 已经满足本地文档搜索引擎的最小功能闭环，适合个人少量文档的实验和后续迭代。单元测试覆盖清洗、分段、高亮、数据库替换和增量索引。

索引链路现在采用“固定大小读取/逐页抽取 → 流式清洗 → 流式分段 → SQLite 批量迭代写入”，哈希计算也按固定大小读取。这样大 TXT/Markdown 不会因为 `read_bytes()`、全文清洗或 `list(chunks)` 同时占用大量内存。

### 已知限制

1. PDF 目前只抽取文本层，扫描版 PDF 需要 OCR，暂未支持。
2. PPTX 暂不抽取图片、图表内部文字和演讲者备注。
3. FTS5 的 `unicode61` 适合英文及空格分词文本；中文连续词在无 FTS5 命中时使用参数化 `LIKE` 兜底，排序能力有限。
4. 搜索使用关键词 AND 匹配，不支持自然语言理解、同义词和语义检索。
5. 暂未实现已删除源文件的自动清理，需要后续增加 `prune` 命令。

### 下一步实验

- 增加中文分词或 n-gram tokenizer，比较召回率。
- 增加 PDF、超长文档和重复索引的基准数据。
- 增加删除/同步策略，再评估是否需要向量检索。
- 增加查询词权重、短语匹配和结果去重，继续观察中文搜索相关性。
